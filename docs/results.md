# Results

Exact Match (%) on fixed-seed 500-question subsets of the Search-R1 eval file
(`PeterJinGo/nq_hotpotqa_train`, split `test`): `nq_dev_500` is drawn from NQ test,
`hotpotqa_dev_500` from HotpotQA dev. Decoding is greedy, retrieval is BM25 over wiki-18
with top-3 docs, and there are at most 4 search turns. SQuAD normalization is used.

The table below is regenerated by `scripts/evaluate.py` (rows are stored in
`docs/results.json`). Numbers are filled in only by real runs. Nothing here is copied from
the paper.

## Milestone 1: GSM8K (single-turn GRPO)

Full GSM8K test set (1,319 questions), greedy, max_new_tokens 300. Trained on a free Kaggle
2×T4 notebook, 200 steps × 64 completions (`configs/gsm8k_0.5b_t4.yaml`, ~4.8 h).

| Model | GSM8K EM |
|---|---|
| Qwen2.5-0.5B-Instruct | 32.4 ± 1.3 |
| + nano-AgentRL GRPO, 200 steps | **47.9 ± 1.4** |

Details and caveats: [experiment_log.md](experiment_log.md).

## Milestone 2: search agent (multi-turn GRPO, Qwen2.5-0.5B-Instruct)

500 NQ + 500 HotpotQA (dev_500 subsets), greedy, BM25 top-3 over wiki-18. Trained 90 steps on
a free Kaggle 2×T4 notebook (`configs/search_0.5b_t4.yaml`, 2.9 h). "gold-in-answer" is the
lenient metric defined in [experiment_log.md](experiment_log.md).

| Method | NQ EM | NQ gold-in-answer | HotpotQA EM | HotpotQA gold-in-answer |
|---|---|---|---|---|
| Direct (no retrieval) | 0.2 | 13.2 | 0.4 | 17.2 |
| RAG (question as query, one generation) | 0.0 | 22.0 | 0.8 | 27.4 |
| **nano-AgentRL GRPO, step 90** | **13.0** | 16.0 | **19.6** | 25.4 |

The RL agent is far ahead on strict EM because it learned the answer format, but it does not
beat RAG on the lenient metric. Read the experiment log before quoting either number.

## How to fill it in (GPU box, retriever on :8000)

```bash
M=Qwen/Qwen2.5-3B-Instruct
for mode in direct rag search; do
  python scripts/evaluate.py --ckpt $M --mode $mode --split nq_dev_500 hotpotqa_dev_500 --use_vllm
done
python scripts/evaluate.py --ckpt PeterJinGo/SearchR1-nq_hotpotqa_train-qwen2.5-3b-it-em-grpo \
    --mode search --split nq_dev_500 hotpotqa_dev_500 --use_vllm
python scripts/evaluate.py --ckpt runs/search_3b/checkpoints/<step> --name ours-3b-it-grpo \
    --mode search --split nq_dev_500 hotpotqa_dev_500 --use_vllm
```

`search` on the plain instruct model is the ReAct-style prompting baseline: the same
Search-R1 prompt and loop, but no RL.
